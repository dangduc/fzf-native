# Bounded SIMD prefilter benchmarks

Date: 2026-09-08T09:37:23Z

This report compares main at `0fb7759` with the SIMD change at `0b3479b`.
Both builds used the same benchmark source and compiler options.

## System

- MacBook Air with Apple M3 and 16 GB of memory
- Apple clang 21.0.0
- Emacs 30.2 development build
- macOS on AArch64

## Change

The change adds two bounded ASCII prefilters.

- The fuzzy prefilter checks an ordered subsequence in each 16-byte chunk.
- The literal prefilter checks two rare query bytes before it verifies a full match.
- The parser builds the query-side SIMD data once.
- All vector loads stay inside the source object.
- Cached refinement batches keep the scalar path because their matches are dense.

The implementation uses NEON on AArch64 and SSE2 on x86-64. Other targets use the existing scalar code.
The public structures and exported ABI do not change.

## Core scorer probe

The probe used 32,768 fixed candidates per case. Each process reported the median of 11 samples.
The table reports the median from seven processes.

The probe is synthetic. It isolates scorer costs and is not holdout evidence.
The literal case has 8% matches. Another 60% has both selected seed bytes but no complete match.

| Case | Main ns/item | SIMD ns/item | Change | Main / SIMD |
|---|---:|---:|---:|---:|
| Early ASCII | 16.27 | 16.72 | +2.8% | 0.97x |
| One byte | 8.00 | 8.03 | +0.4% | 1.00x |
| Chromium fuzzy shape | 51.85 | 45.32 | -12.6% | 1.14x |
| ASCII literal | 38.21 | 29.14 | -23.7% | 1.31x |
| Arabic | 165.47 | 165.31 | -0.1% | 1.00x |
| Korean | 188.11 | 188.63 | +0.3% | 1.00x |
| UTF-8 hit | 437.93 | 437.56 | -0.1% | 1.00x |

The useful shapes improved by 1.14x and 1.31x. The Unicode paths stayed effectively unchanged.
The short ASCII paths also stayed close to main.

## Literal threshold sweep

A separate harness tested 644 cells. It varied query length, candidate length, case mode, API, hit rate, and false-seed rate.
All hit counts and fingerprints matched main.

The table reports `SIMD time / main time`. A value below 1.0 is faster.

| Candidate shape | 32 starts | 128 starts | 512 starts |
|---|---:|---:|---:|
| Clean miss | 1.024 | 1.008 | 1.008 |
| Reachable false seeds | 0.543 | 0.411 | 0.261 |
| 100% early hits | 0.876 | 0.868 | 0.860 |
| 10% late hits | 0.832 | 0.615 | 0.409 |

A 24-start threshold made scored matching 16% to 34% slower in tested cells.
The implementation therefore enables the literal prefilter at 32 possible starts.

## Interactive edit trace

This trace used 200,000 candidates, one worker, a 256-result limit, and seven samples per process.
The result is the median from six processes with reversed run order.
The trace validated every result against an independent full scan and sort.
The measurements do not include confidence intervals.

| Phase | Main ms | SIMD ms | Change |
|---|---:|---:|---:|
| Full trace | 297.495 | 301.362 | +1.30% |
| Narrowing edits | 226.116 | 229.142 | +1.34% |
| Unrelated edits | 71.375 | 72.057 | +0.96% |

Backspace requests were exact cache hits and took about 0.002 ms to 0.006 ms.
That duration is too small for a useful comparison.

Eight-worker measurements ranged from 35 ms to 80 ms. This report excludes those unstable measurements.

The trace keeps scalar matching for cache-selected refinements. It therefore measures integration overhead, not the SIMD gain from full-pool scans.

- `make ctest` passed.
- `make ctest-asan` passed with AddressSanitizer and UndefinedBehaviorSanitizer.
- The Emacs 30.2 suite passed all 188 tests with the new module.
- The matcher fuzz corpus replayed 12 inputs.
- Both interactive fuzz targets replayed 18 inputs.
- Both interactive fuzz targets passed ThreadSanitizer replay.
- The CMake release module built successfully.
- A direct helper harness passed 2,383,861,238 checks on NEON and SSE2.
- The same helper harness passed optimized and sanitizer builds.
- A plan-layout harness passed 35,808,327 checks.
- An end-to-end differential harness passed 600,000 checks across 200,000 cases.
- A public API differential run produced the same result hash on main and the SIMD build.

The x86-64 SSE2 implementation also ran under Rosetta. Pull request CI must provide the final MSVC x64 build check.

The direct property and differential harnesses are not part of this repository.

## Limits

This run did not repeat the `fuzzy-benches` or Frizbee holdouts.
The core probe and threshold sweep only support the local fast-path decisions in this change.
They do not establish a general cross-library performance result.
The measurements do not establish performance on native x86 hardware or Windows.
